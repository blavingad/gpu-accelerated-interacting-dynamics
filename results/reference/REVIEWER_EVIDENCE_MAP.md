# Digital raster-development methodology: claims and evidence

The industrial purpose is to reduce repeated physical-rig iterations and engineering effort across raster and printhead-development programs. The scientific contribution is the explicit, testable development process and its field/interaction decomposition. Savings are an intended outcome, not a measured result of this study.

| Question | Evidence supplied | Claim boundary / next action |
|---|---|---|
| What design space is covered? | 95 declared printable glyphs, 224 nonblank font masks, 235 current-only baseline/font cases, 644 ordered previous/current cases per evaluated raster | Exhaustive only within this declared finite pool; no claim about all binary masks, arbitrary preceding streams, geometries or continuous settings |
| Is history actually simulated? | Preceding and current emissions, continuous charging state, active-particle forces; matching ordered context selected during rendering | Older stroke blank, no following emission; local dependency window limits table representation, not physical interactions |
| Is every lookup address characterized? | Internal required-key map and full binary-address map retained separately | Unseen addresses must not be presented as optimized or validated |
| Is it faster? | Synchronized matched batch64 benchmark: 15.75s GPU versus 82.53s CPU, 5.24x warmed execution on this workstation | Not a benchmark against a rig, not a universal GPU ratio; report compilation, output mode, transfers and batch padding |
| Does broader coverage matter? | Same isolated seed, same bounded update/pass policy, three development sets; frozen assessment on all 644 contexts | Costs differ with development set size; bounded experiment is not a converged-design or equal-total-budget algorithm contest |
| Is structure discovery exhaustive? | Archived million-candidate surrogate screen, 512 selected structures and 3321 coupled evaluations including probes/refinements | Bounded exploration; no global optimum and no count of probes as distinct structures |
| Are numerical equations preserved? | Original-kernel parity, charging matrix/sequential parity, native-case comparison, synthetic analytic limit, targeted step probe | CPU/GPU event crossings can differ by a native step; industrial field-grid convergence and closure-sensitivity studies remain open |
| Is hardware deployment demonstrated? | Author-reported table deployment and independent glyph-coordinate extraction; fixed native75 command replay | Measured endpoints assess the two tested operating points; no assertion that every force, collision or geometry is independently validated |
| Are experimental samples independent? | 26 separately printed glyphs per case, author-reported; 1725 matched dots per case | Glyphs are not repeated identical-print trials; no repeatability interval from dot count |
| Are uploaded revisions repeats? | Raw versions, hashes and residual-scaling audit retained | Revisions are not pooled as independent acquisitions; upstream metrology/processing record still needed |
| Can others reproduce it? | Equations, algorithms, benchmark protocol and local synthetic package without industrial data | Industrial field and tables withheld; synthetic reproduction does not reproduce industrial outcomes; source disclosure approval before public release |
| Is GNN performance established here? | Versioned physics data interface and frozen assessment definitions | No experimental GNN result claimed in this paper |
| Are department-level savings quantified? | Prospective cost protocol below | Not yet; measure equivalent end-to-end development tasks |
